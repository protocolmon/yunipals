Ordinary V5 generation preparation
=================================

This source-only slice prepares V5 generation/cache selectors and a single new
native generation, using the actual new V5 metadata owner and current ordinary
source callback. Historical48cc/3d42/c65 files, namespaces and receipts stay
unchanged. No old current-source constructor is called. It does not publish a
generation, switch a reader/cache, grant permissions or activate recurring work.

The new candidate producer uses the actual metadata candidate input (which binds
ordinary source, V5b read admission and created V5). It renders only the existing
five leaderboard and four cache public selectors into a fresh protected path.
Existing private environment files and credentials are retained. It qualifies
the actual installed official source closure, original generation103, all35
legacy guards, four read epochs, dormant cache role and real writer frames.
New intent/result and exact file hashes authenticate the candidate; unknown or
partial staging refuses automatic continuation.

The generation producer compiles unchanged48cc effect, capsule, held-SQL,
unknown-ACK and activation-inverse bodies into new globals. Its fixed component
routing returns the genuine new V5 metadata namespace and selector producer;
this preserves the constructor's PROPS/operation/cli_context API instead of
pretending the metadata CLI wrapper has those fields. Its extra constructor
checks the actual new selector intent/result/READ scope. Candidate format,
BASE, unit, runtime directory and monitor paths are new. Frozen B45 capsule,
6cba guard, f81 compiled worker and installed runtime remain exact.

The monitor preserves pool4,25GB reserve/30GB abort floor,1470s supervision,
1500s service RuntimeMaxSec and original backup exclusion logic. Its typed
backup timer decoder accepts genuine D-Bus uint64 scalar or the existing exact
single-element representation; booleans, negatives, unknown types and shapes
refuse. No deadline or storage bound is loosened.

Commands and real prerequisites
------------------------------

Root owns publication, staging and every host effect. Default source invocation
is static. After the actual V5 metadata candidate input exists, run:

  ypal-ordinary-generation-candidates-v5.py --candidate-input-sha ACTUAL_INPUT_SHA

It returns only aggregate reviewHash. Add --stage ACTUAL_REVIEW_HASH to stage the
four public selector/drop files exclusively. Actual receipt is returned. No
worker, SQL or service action occurs in this candidate stage. The fresh path is
/var/backups/yunipals-ypal-ordinary-generation-candidates-v5-20261025.

After actual metadata drain/adopt/select and complete canonical provenance,
invoke ypal-ordinary-generation-v5.py with all original48cc arguments:
--read-ack, --install-ack, --metadata-operation, --metadata-selected,
--metadata-provenance, --metadata-provenance-sha and --metadata-input-sha;
also supply --selector-candidate-sha ACTUAL_NEW_SELECTOR_RESULT_SHA.
All refer to real new receipts; old/V4 or future values are ineligible.

Default with those refs performs nonmutating actual review. Only its exact
reviewHash may authorize --phase drain --ack REVIEW_HASH. Later capsule/build/
accept-candidate phases use the actual operation hash through --ack. The original
reconcile-capsule/reconcile-build and restore-activation/reconcile-start behavior
is retained. Never repeat uncertain SQL or a start. A failed review leaves
unknown prefixes preserved; no journal removal or relabeling is allowed.

A real new capsule captures original103/prior/wallets/two stamps before the
single prepare worker. A built ready candidate remains unpublished; exact
generation ID/source snapshot/readIdentity/validation and capsule ancestry are
recorded in the new protected candidate-result.json. It must not be substituted
for103 or treated as published/reader acceptance. The source-independent export
validate_candidate_database_current(actualCandidateSHA) rechecks only database,
immutable lineage/capsule and artifact facts; caller owns source/role/metadata/
cache/current-serving qualification. Initial forward CLI uses the current
ordinary standalone writer. A later managed writer needs its own explicit
current phase context; no standalone receipt is a managed epoch.

Validation and limitations
--------------------------

python3 -I -B ops/unified-indexer-transition/ypal-ordinary-generation-v5.test.py

Seven isolated controls execute genuine namespace/effect bodies, actual reused
constructor routing, exact selector counts, actual metadata wrapper API, timer
shapes, and exact unit/capacity/runtime limits. Source tests do not establish
production disk headroom, a backup-free25-minute window, actual generation
runtime, capsule capture, metadata adoption or reader cutover. Root must qualify
those real prerequisites at each existing phase gate. Detailed runtime/writer/
private observations remain under the protected metadata input directory;
stdout exports aggregate phase/hash flags only.
