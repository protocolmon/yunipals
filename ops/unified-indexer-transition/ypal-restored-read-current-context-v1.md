its distinct de4/0ee original-pool-five epoch, and the unchanged READ143 logical
scope. It never calls the earlier context's c96 runtime validator, `c9.load()` or
an old view constructor. All historical helpers, SQL, plans and receipts remain

The interfaces agreed with the new coordinator and permission-provider authors:

- `validate_runtime(rpc_pin=actual1521)` returns the stable flat994 source binding.
  Source heartbeat, checkpoints and observed framework readiness are excluded.
  This grants no reader, Arena, READ143, canonical or financial authority.
- `observe_runtime()` returns `{binding, observation}` for separately qualified
  mutable native observations.
- `load_components()` returns named current objects, never an old bootstrap tuple.
  `readerHost` supplies bounded single-selector READ ONLY queries and one fixed
  owner RR catalog capture. `historicalReadHelpers` exposes only unchanged pure
  edge/delta/statement helpers; `historicalReadPlan` remains the exact fc79 scope,
  not a new acknowledged plan. `catalogSql` is unchanged cd1.
- `privilegedSourcePrimitives` separately names the pinned restoration/recovery
  modules, SDK, current underlying host, actual current source and historical
  ancestor operation. These are low-level components for a separately reviewed
  owner; they do not confer a new grant, transaction or financial authorization.
  No generic write or transaction CLI is added here.
- `reader_host()` returns only the bounded read interface.
- `arena_admission(config)` explicitly authenticates the existing admission/auth
  chain and current9-role/13-read catalogs through their pinned owners. It does
  not use an obsolete source actor. Actual acknowledgement inputs are mandatory;
  null values remain closed. This verifier does not create or configure a role.
- `validate_baseline_catalog()` and `validate_feature_catalog_order()` call only
  the earlier context's unchanged pure ordering helpers. Actual Arena13 admission
  must precede the new READ baseline, and its intersecting Meta/checkpoint edges
  must already exist in both feature before/after catalogs.
- `validate_before_baseline(input_sha)` returns the same baseline-record shape:
  actual restored runtime, current Arena proof, full RR catalog, exact historical
  143 permission statements and ordering evidence. It verifies source/Arena again
  after capture, and refuses any existing feature operation.

The exact seven existing-role/table/function scope and before/after/direct-column

is inferred from the Arena baseline. The cd1 catalog is not represented as a
complete all-grantee target-column authority: the broader separate full-column

No fresh READ143 plan, before/rehearsal/commit ACK or cache ACK is manufactured.
`actualNewReadAdmissionQualified`, `actualNewCacheAdmissionQualified` and
`terminalInverseSourceQualified` remain false. The new provider must supply its
