SEQUENCING AND CAPACITY

Use owner-v5 / preview-v5 / install-v6 together; do not feed a new preview receipt
to an old installer or force the role back to NOLOGIN to satisfy an old helper.
The new pins form an acyclic dependency chain. The JSON evidence beside this
runbook records every actual source hash.

Keep the existing coordination order: admit/review finite ACLs, qualify all
positive retained-route previews, then perform sequential final installs. Main
write slices still need a successful new main preview with the same action-read
receipt and real full-receipt BNB fixture. Cache install retains the actual v4
generation/native-guard/freshness checks and its bounded worker wait. No BNB,
generation or marketplace requirement has been added to the booster API.

Collector uses max2 feature API + max1 artwork queue + max2 candidate API + one
bounded peer probe = the existing role limit6. The peer probe completes before
steady-state observation/ACL execution; it is not a permanent application-name
exception. Only the two fixed feature application names are excepted from the
old zero-session ACL guard. Candidate sessions must still be absent for those
ACL transactions. A final admitted collector can coexist with subsequent final
consumer installs through its exact new install receipt, unit/invocation, input
hashes and process proof. Never overlap collector preview and final candidate.
Keep the existing global PostgreSQL reserve/capacity check too.

The collector entrypoint's accepted routes use the two-slot apiPool; the other
offchain pool is lazy and unused on these routes. Requalify that property for
the exact pinned final artifact. Starting to use a two-slot worker pool would
exceed this allocation and is refused; do not raise the role limit.

The new operational ACL/preview phases deliberately precede final collector
installation. Do not use them as general maintenance commands after unrelated
reader admissions. A change to the separately owned static feature inputs needs
a new acknowledged baseline/successor; a stale receipt cannot authorize it.
