  --plan ACTUAL_PROTECTED_PLAN --plan-sha256 ACTUAL_PLAN_SHA256

This creates only the fresh owned scanner runtime/public files and boot path. It does not select it. Observe real catch-up and require the adapter's complete canonical coverage before continuing. Scanner logs contain only public block/status/counter summaries.
2. Run default review. It checks actual latest native actors/boot paths, original auth graph, predecessor epoch, retained private ledger, isolated target grants and fresh canonical coverage. A moving complete head is revalidated without making an otherwise fixed review stale; identities, private history, floor and actors remain hash-bound.
3. Run `--prepare RECOVERY_REVIEW_HASH`. It records immutable intent, preserves exact native unit bytes and boot-link inodes, holds only those native boot paths and drains those exact eight compatible actors. It halts the unified operational deployment under the exclusive source lease and emits/fsyncs its transaction ID before COMMIT.
4. Preparation runs the official `ArenaSourceSwitch` in review mode while halted. Inspect its actual accepted floor, canonical openings/freeze/input/result/film witnesses and private-record digests. ## Failure and acknowledgement handling

Always use `--reconcile` first after a source SQL acknowledgement is uncertain. It is read-only and checks actual `pg_xact_status` for every fsynced owned XID, exact selector/predecessor, full native identities and the retained ledger. A matching after-graph alone is insufficient. Unknown/in-progress transactions, foreign epochs/files/boot paths or changed immutable private inputs refuse.

- Lost halt ACK: `--finish-prepared` requires the exact committed halt XID, same operation/boot, terminal native workers and fresh target proof. It only captures the official source-switch review; it does not repeat the halt SQL.
- Lost publication ACK: after reconciliation confirms the exact owned selector commit, use `--continue-published OFFICIAL_REVIEW_HASH`. It never reissues selector SQL. Exact installed source-file inodes may finish their ACK; unacknowledged starts may be adopted only inside their recorded initial window with exact native commands/definitions. It does not blindly issue another start.
- Lost unhalt ACK: continuation requires the actual committed owned unhalt XID and exact selected epoch, not just `halted=false`. It completes the final receipt without another SQL transition.
- Before **any** publication intent, `--abort-review`/`--abort-before-publication ABORT_REVIEW_HASH` can restore the same modern predecessor workers/boot paths after proving that current source is canonical and sufficient. This is not the pre-adoption old-runtime inverse. If the original source is unavailable, the owner leaves consumers safely halted instead of inventing coverage.
- Lost initial scanner start ACK: `--scanner-inspect` then `--ack-scanner-start INSPECTION_HASH` can acknowledge only the same initial start window, exact public bytes/config/boot, no restart and matching DynamicUser command/cgroup. No start is repeated.
- Lost scanner stop/boot-unlink ACK: `--finish-scanner-stop` requires its exact stop intent, terminal/no-job manager state, a completed canonical native return and the original boot inode or its acknowledged removal. It performs no service retry and cannot disable another scanner's path.

An incomplete boot drain, failed source precondition, restart outside its owned start window or other unacknowledged state may require a new concrete reviewed finish action. The owner refuses such unknown states. Do not replay its initial command, manually reset cursors, clear a history-change halt, relabel native records, delete selectors/history, re-sign saved transactions or restore an older private database.

If the isolated confirmed cursor detects a reorg, the official scanner halts rather than resetting accepted history. Select a separately prepared fresh public projection only through another canonical review; this package does not resolve durable orphaned rights automatically.
