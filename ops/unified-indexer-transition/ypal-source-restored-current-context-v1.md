# Actual restored-pool-five source context

This new source-only context pins the actual `de4` restoration producer and its
`0ee` receipt. It never calls `47ab.validate_source_current(restored=True)` and
never treats the restored process as the historical c96 actor. The old pool-eight
context and previous current-read contexts remain unchanged.

The fixed restoration validator checks the new actual epoch, original pool-five
configuration, six original mounts, private arguments, heartbeat and retained
native recovery floors. This context additionally verifies the registered 4e
release, build 71e, full manifest and native 44-table/cache identities. It requires
the independent nine-RPC component with its actual acknowledged producer and
component hashes. The original legacy writer remains terminal with retained
native history. It never imports a Ponder application or performs provider,
service, grant or SQL-write actions.

`validate_runtime()` returns a stable source binding.
`observe_runtime()` returns `{binding, observation}`. Two genuine restoration
validations surround the registered-manifest read. SDK actor, original boot
inode, source epoch, native table/cache OIDs, config and RPC scope must agree.
Only the already reviewed After-token-order canonicalization from the restoration
validator is used for that SDK actor. Advancing heartbeat/checkpoints and observed
framework readiness stay in the separate observation and cannot create false
binding drift.

The binding records the actual restoration producer, receipt, own start intent,
original configuration and absence of an active pool-eight overlay. Registered
base inventory and c96/partial47ab receipts are explicitly historical ancestry.
It does not claim a 47ab inverse success, a pool-eight runtime, current canonical
coverage, framework readiness, reader roles, Arena, READ143, financial authority
or current writer-session attribution. Those remain separate downstream gates.

The pure ordering/catalog helpers from earlier contexts may be explicitly reused
by a new downstream producer. Their obsolete runtime validator must never be
patched, bypassed or reported passed. A later process restart needs its own
explicit epoch qualification; this context does not silently accept another PID.

Stage the public source at the fixed operations path. Default execution is static
and makes no runtime qualification claim:

```bash
python3 -I -B /opt/yunipals-unified/operations/free-replay-20261020/ypal-source-restored-current-context-v1.py
```

The explicit runtime command performs bounded read-only validation and returns
only the stable binding hash:

```bash

```

Detailed actual bindings and observations remain private. Raw checkpoint fields
in the observation are not a complete-checkpoint or canonical witness.


Twelve controls cover progressing observations, foreign same-count OIDs/cache,
actor/config/boot/manifest drift, wrong producer/receipt/pool, old-receipt
relabeling, authority escalation and protected-file substitution. They perform
no host or provider calls.
