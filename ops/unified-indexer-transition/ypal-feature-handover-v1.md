## Review and effects

Run from the fixed production host/root only. Default is read-only. The following
are command shapes; every capitalized SHA/review value must come from an actual
protected file/result, never a guessed future value.

```sh
python3 -I -B /opt/yunipals-unified/operations/free-replay-20261020/ypal-feature-handover-v1.py --manifest-sha CODE_MANIFEST_SHA --input-sha CONFIG_SHA
```

Supply the returned exact fresh review hash to `--rehearse REVIEW_HASH`. This
creates a fresh0700 evidence directory and performs the exact catalog-CAS
transaction ending ROLLBACK. The complete collector graph must be unchanged. Full target column ACLs are
compared too; an existing collector column SELECT overlapping a new table SELECT
requires separate review because PostgreSQL table-level REVOKE also removes it.
Other grantees’ column ACLs are retained byte for byte in the catalog proof. Effective column writes,
including PUBLIC grants, and filtered/RLS native tables are refused.
`--admit OPERATION_SHA` performs the one separate eight-SELECT COMMIT with the
writer grantor and exact before/after checks. Unknown acknowledgements are not
retried. No source-readiness claim is made by read admission.

For the switch add `--capture-id initial-prefix --parity-sha ACTUAL_CAPTURE_SHA
--canonical-file ACTUAL_HEADER_FILE --canonical-sha ACTUAL_HEADER_SHA` and run
`--switch-review`. Apply with `--switch EXACT_SWITCH_REVIEW_HASH` and identical
inputs. The owner rechecks parity/current canonical evidence before the first
service effect. Actual existing local/public fresh-serving HTTP is also proved
before stopping its healthy API/timer. Both sources stay live. It pauses the existing queue timer,
drains queue/API, writes only its new public schema selector and two97 drop-ins,
reloads definitions, starts the same API program, proves actual local/public
fresh-only types/global/recent reads and approved standard art, runs one queue

Base-scoped complete/canonical freshness is checked separately. The accepted
Ponder adapter treats a partial raw checkpoint as complete through rawBlock-1;
the adapted complete block must cover the required boundary. A raw partial
checkpoint at the boundary itself does not suffice. The fresh-header deadline
is checked after all final reads, immediately before the first manager call. The unchanged
41fe API also requires the framework `is_ready` bit. Switch-review therefore
refuses before stopping the healthy API while that bit is zero. It never changes
the flag or claims all configured chains were independently qualified.

Retirement is separate. After the switch, wait for a genuine newer event; do not
create a transaction for this proof. Supply its exact JSON
`{"blockNumber":N,"blockHash":"0x...","transactionHash":"0x...","logIndex":I}`
with `--event`, a new post-event full-eight named capture/header, and

No command stops the combined source, changes profiles/budgets/expiry, calls a
provider, signs or transacts onchain, changes source selectors, publishes a

## Inverse and uncertain outcomes

`--inverse-review`, then `--inverse EXACT_REVIEW_HASH`, restores a completed owned
switch/retirement. Its separate inverse-only source predicate can accept the
combined source terminal with exact owned static/boot/role/proxy/native-OID
proof; it never starts or stops that combined unit and never calls this a
healthy forward source. A terminal owned API can be restored from static and
empty-process proof. An API automatic restart is accepted only for inverse with
exact97 inodes/program/private/public inputs, its owned start epoch, a positive
manager restart counter and the actual UID967 kernel/socket-to-PG identity.
These facts are rechecked before effects. Inverse mode cannot authorize any
forward entry point. If retired, it restores only its archived original scanner
boot inode, starts the retained temporary YPAL source with a fresh owned actor
and proves fresh native catch-up first. Its restored source must cover the last
accepted feature cursor, rechecked again after the new API drains, before any
old-schema API is started. It then pauses/drains the feature,
unlinks only exact owned97/schema-selector file inodes, starts the original
program on the fresh YPAL schema with a fresh API actor, synchronizes/resumes the
queue, and revokes only its eight reads. It never restores old PROTO serving or
rewrites the original source/reader receipts. Prior143/cache4 reads remain.

All step intents are fsynced before effects. A preexisting intent cannot cause an
automatic repeated start/COMMIT. `--inspect` only observes safe manager fields and
the exact action journal. Incomplete filesystem publication, unknown manager
ACK, partial retirement, unknown COMMIT, or interrupted inverse may need narrow
manual reconciliation; v1 does not adopt an unacknowledged prefix or infer a
successful final receipt. Do not rerun an effect or drop a schema to clear it.

`validate_current(retirement_sha, manifest_sha, input_sha)` is the strict original
combined-actor/current-feature predicate. `validate_feature_leaf(...)` is a
separate read-only export for a later explicitly reviewed supervisor: exact
owned API/private inputs/overlays/ACL/event-retirement facts, but **no** source
actor, financial, peer lifecycle or all-chain authority. Forward CLI actions
never substitute that leaf for their strict source predicate. A new supervisor
must independently supply its own exact acknowledged source/runtime/financial
proof and bind this producer/receipt.
