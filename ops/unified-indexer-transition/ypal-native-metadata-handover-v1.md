# Native metadata handover: explicit reviewed phases

This owner coordinates the existing metadata writer and its original restart
path with the unchanged official metadata CLI. It is not a general SQL or
service operator. Source, profile, launch API, artwork queue, other workers,
roles and financial authority remain governed by their own acknowledgements.
No production-derived observation or private receipt should be published with
these sources. Keep every actual review and result protected on the host.

The fixed dependencies are the metadata candidate producer `146128b9…`, its
acknowledged dormant candidate result `21cb9989…`, normalized runtime `cf333946…`,
and corrected read-admission producer `c9b54f2c…` at
`/opt/yunipals-unified/operations/free-replay-20261020/ypal-combined-read-admission-v2.py`.
Supply the actual successful read-admission result SHA to every command. The
owner never invents that receipt, normalizes the old catalogue, or claims the
old whole validator passed. The admission verifier intentionally leaves this
separate owner's metadata process/mode/selection ownership checks to it.

## Official implementation retained

The staged `native-recovery.sh` loads one identical private environment into
Node and the CLI and invokes the exact normalized `unified-base-metadata.mjs`.
The original keys, database credential, existing database role and provider
configuration remain in their protected files. The only selected configuration
changes are the already acknowledged six public selectors and normalized
worker command. Base point calls use the combined proxy's ROOT route; no custom
head scanner or source-policy header bypass is introduced.

`native-adopt` holds `metadata:base-replay`, compares all legacy/native decoded
tuples in sixteen hash partitions under repeatable read, checks canonical Base
headers/implementation through four bounded point calls, and commits native
scan mode plus the fresh approval. It preserves the original exclusive cursor.
The normal native worker then maintains the short-lived approval; adoption by
itself is not a permanent readiness witness.

`native-provenance` first invokes official refresh, then stamps at most5000
eligible records in one transaction. It also upgrades only the matching already
published request identities. In-flight, missing or mismatching proofs are not
manufactured. A busy result is recorded as busy. One batch is not a completed
backfill. The owner permits at most128 individually reviewed batch indices,
with each preceding attempt acknowledged; it never loops automatically.

## Review and drain

Default execution is a read-only review apart from the private mutual-exclusion
lock. Root must capture detailed output locally. It validates the actual read
admission, immutable source/read-view/candidate bytes and current legacy writer,
ordered private configuration, sole boot activation and job/cgroup state.
Actual Base coverage must reach the current legacy cursor; a fetch metric,
standalone launch readiness or a fabricated frame cannot satisfy that gate.

```sh
python3 -I -B /opt/yunipals-unified/operations/free-replay-20261020/ypal-native-metadata-handover-v1.py \
  --admission-result-sha "$ACTUAL_READ_ADMISSION_RESULT_SHA"
```

Only append `--apply "$EXACT_PHASE_REVIEW_HASH"` after reviewing that fresh
result. This first phase exclusively creates
`/var/backups/yunipals-ypal-native-metadata-handover-v1-20261024`, saves its actual
operation hash, preserves the original boot symlink inode outside systemd's
activation tree and reloads. It recaptures positive kernel-FD ownership of the
metadata backend subset immediately before the stop intent, fsyncs that proof,
checks the same actor after the intent, and stops only that unit once. The shared
DB role's other clients are not assumed to be metadata clients. Terminal
acceptance requires the owned cgroup/process identities and fresh backend tuples
to be gone; a new unattributed shared-role session causes explicit refusal.

The stopped cursor and actual native frame are saved after the drain. No
mode, journal, publication, role or source is modified by the drain phase.
No unrelated writer or backend is terminated.

## Adopt, select and observe

Every subsequent phase first needs the actual protected operation SHA:

```sh
python3 -I -B /opt/yunipals-unified/operations/free-replay-20261020/ypal-native-metadata-handover-v1.py \
  --admission-result-sha "$ACTUAL_READ_ADMISSION_RESULT_SHA" \
  --operation-sha "$ACTUAL_METADATA_OPERATION_SHA" --phase adopt
```

Review, then append that phase's exact `--apply` hash. The owner requires the
unchanged stopped RPC cursor, no pre-existing fresh-release approval, covered
native frame and disabled original boot path. It invokes official adoption once
and saves both its actual result and observed native state. It does not advance
or reset the cursor itself.

Use the same review/apply pattern with `--phase select`. This installs only the
acknowledged metadata drop-in into its previously absent fixed path and records
its actual inode. Original private definitions/files remain exact. It writes a
start intent before one start, verifies the compiled native command, same
configured environment, UID/group, owned cgroup and start boundary, and observes
three genuine native approval/probe samples ten seconds apart. It restores the
same original boot inode only for the accepted native definition. Other services
are neither reloaded individually nor restarted by this owner.

Complete selection promptly after adoption. The native worker maintains approval
while later, separately reviewed provenance batches run. Selection is not proof
that publication backfill is finished.

## Bounded provenance and completion

Review/apply `--phase provenance --batch-index 0`, then each next canonical index
once only. The actual official stamped count and post-phase remaining published
records without native hashes are preserved. Unknown or failed preceding batch
acknowledgements block advancing silently to a different index.

Completion is conservative: zero remaining active archived/published Base rows
without native hashes, a fresh native probe, and equality of the published count
with the canonical count produced by the unchanged official bulk metadata read
relation. That relation validates current canonical mint/lifecycle and latest
metadata event/hash, archive availability and publication runtime. A non-null
hash alone does not qualify. Historical or unmatched rows are retained and
reported rather than deleted or relabelled to make a count pass. There is no
automatic retry or batch loop, generation refresh or cache guard migration.

## Uncertain acknowledgements and inverse

`--operation-sha ... --inspect` reports current owned phase files/state without
service/DB actions. `--reconcile` additionally checks recorded CLI identities,
refuses a live child, and reports terminal semantic adoption/inverse/start
postconditions without reissuing the uncertain command. A semantic state is
labelled separately from the missing original CLI acknowledgement; it does not
fabricate parity output, a transaction ID or a successful manager call.

The explicit `--phase inverse` review/apply stops only the fresh actor qualified
against the owned drop inode/start intent, with a new backend ownership capture
and post-intent actor CAS. It first disables the same boot inode. The old writer
cannot restart until the native cgroup and mapped sessions are terminal. Under
the official advisory lock, the fixed inverse transaction CAS-checks every saved
cursor field, native mode and fresh-release approval identity, returns scan mode
to RPC and blocks only that approval. It never deletes or resets journals,
publication hashes/request identities, source checkpoints, grants or generations.
A pre-adoption partial prefix already in original RPC mode needs no inverse SQL.

It removes only its own exact drop inode/bytes, restores original loaded
configuration and the preserved boot inode, checks all original private values,
and starts the original writer at most once under a durable start intent.
Restoring a service is not a source rollback or metadata data restore.

After inspecting a failed inverse, review/apply `--phase finish-inverse` only for
the existing owned inverse intent. It can finish equal filesystem unlink/publish
prefixes, consume an already proved loaded/terminal state, recognize already
restored RPC mode plus the owned blocked approval after lost SQL ACK, or recognize
a correctly started original actor. If that exact restored RPC actor has already
advanced its cursor, finish-only acknowledgement permits monotonic progress after
checking the original private configuration, boot/start intent and owned inverse
approval. The start intent also captures its exact pre-start RPC scan, so this
works for a pre-adoption stopped prefix whose drain receipt was never saved;
when a drain receipt exists its cursor must match. The original actor and boot
are checked again after observing the resumed database state. Cursor equality remains mandatory before native-to-RPC SQL and before a
new start. No SQL or manager action is reissued by this owned-resume branch.
It never repeats an uncertain SQL, stop, start or reload. If the effect cannot be proved, it refuses and reports unknown;
manual reconciliation remains necessary. A missing drop inode receipt or missing
CLI child identity is also refused rather than inferred from matching bytes.
A completed inverse cannot run again.
