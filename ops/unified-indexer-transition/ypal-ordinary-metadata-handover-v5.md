Ordinary V5 metadata handover
============================

This slice prepares fresh private V5 selectors and runs the existing metadata
lifecycle in its own namespace. It never adopts V4, relabels old receipts or
calls old de4/c96 current-source constructors. Initial writer qualification is
actual ordinary3bf through5a1; immutable c2da143 ancestry plus the actual new
V5b logical-grant receipt is a separate permission domain. No new ACLs are
performed by this slice.

The new common module compiles unchanged146 render/retarget helpers with V5
schema/identity and a new candidate directory. It copies the four authenticated
dormant candidate files, changes only the original six public selectors, and
preserves all other environment values, credentials and the installed metadata
worker. It qualifies the actual legacy role/cursor, new grant catalog, current
ordinary writer, exact created V5 objects and private configuration on both sides
of the staging write. A partial stage is retained and refuses automatic retry.
Its exclusive result must equal its exclusive intent plus the three stage flags.

The metadata owner reuses cf779 drain/adopt/select/provenance/inverse/unknown-ACK
bodies with a new producer/BASE/drop. Its explicit constructor authenticates the
actual V5 creator, V5b admission reference triple and staged private candidate
receipt/files. SQL sessions use host(client_addr), and captured client FDs must
match the actor's kernel startTicks. Terminal checks drain only positively owned
backend epochs, allowing unrelated shared-role reconnects. An already-terminal
worker requires its exact acknowledged invocation, private/loaded/boot/drop
phase, dead owned processes and positive residual-peer kernel attribution; an
unknown invocation or orphan refuses. Current writer and read-graph checks remain
separate phase callbacks. No whole historical validator is declared passed.
