# Restored-source YPAL feature handover

Source preparation only. No grant, reader selection, scanner retirement, or
readiness is claimed by this package. All actual operation inputs and reports
remain root-private on the host. Historical e506 and its receipts stay unchanged.

The new owner reuses the frozen e506 transaction, file, API, queue, retirement,
and inverse bodies in a new namespace. Nine Host construction/current-source
methods are explicitly replaced. One additional start boundary checks that the
target is still terminal after the final preservation observations. The original
eight grants, complete ten-table ACL/column checks, all-eight parity SQL, genuine
post-switch event, native/framework gates, and receipt protocols remain intact.

## Required actual inputs

An operator creates a fresh root-only input directory at
`/var/backups/yunipals-ypal-restored-feature-input-v1-20261024` and writes
`config.json` with the seven actual hashes shown in the example. Null examples
cannot run. The READ plan and ACK must come from the new restored admission
producer. Cache inputs, prepared ACK, authorization, SQL intent/prepared/XID and
committed postProof must belong to the restored cache producer. The completed
three-reader result and its external manifest must belong to reader-v2.

The constructor authenticates immutable receipts and static query primitives.
It does not call an old c9/view/c96 constructor or a reader leaf. The reader
coordinator's pure `core` and `published` functions authenticate its complete
operation/publication intent/XID/packet chain without making a reader Context,
opening an application Pool, or checking a source actor. Current collector state
is compared to the acknowledged cache `postProof.reader`; the new READ before
record is never assumed to have the old `readerBefore` field.

Forward service boundaries explicitly require the actual de4 restored pool5
epoch through e82 and RPC-v3. Inverse boundaries use the separate fbb active-or-
terminal source proof. Those are source gates only; canonical/frame/role authority
comes from the separately owned phases. No expired profile, changed budget,
missing ACK, or unknown process is normalized into acceptance.

## Explicit phases

Install only the finite public source packet after independent review. Keep the
input directory and operation directory root0700 and input/report files root0600.
Set `MANIFEST_SHA` and `INPUT_SHA` to the reviewed actual bytes. The executable is
`/opt/yunipals-unified/operations/free-replay-20261020/ypal-restored-feature-handover-v1.py`.
The following commands illustrate separate operator phases; placeholders are not
actual authorizations or acknowledgements.

```text
python3 -I -B OWNER --manifest-sha MANIFEST_SHA --input-sha INPUT_SHA
python3 -I -B OWNER --manifest-sha MANIFEST_SHA --input-sha INPUT_SHA --rehearse REVIEW_HASH
python3 -I -B OWNER --manifest-sha MANIFEST_SHA --input-sha INPUT_SHA --admit OPERATION_SHA
python3 -I -B OWNER --manifest-sha MANIFEST_SHA --input-sha INPUT_SHA --capture-id CAPTURE_ID --canonical-file FIXED_CANONICAL_FILE --canonical-sha HEADER_SHA --parity-sha PARITY_SHA --switch-review
python3 -I -B OWNER --manifest-sha MANIFEST_SHA --input-sha INPUT_SHA --capture-id CAPTURE_ID --canonical-file FIXED_CANONICAL_FILE --canonical-sha HEADER_SHA --parity-sha PARITY_SHA --switch SWITCH_REVIEW_HASH
```

Default review is read-only. Rehearsal is a real ROLLBACK of exactly eight new
collector SELECTs. Admission is one explicit COMMIT. The switch stops only the
owned queue timer/queue/API and appends the new `98-ypal-restored-combined.conf`
overlay; programs, private inputs, addresses, roles, budgets and old95 overlay
remain the same. Both source framework gates and old public/local API readiness
must pass before the first stop. The canonical deadline is checked immediately
before that first effect. Do not claim zero downtime across the reader restart.

After a genuine later event, capture a distinct named all-eight parity receipt
and supply a separate fresh normalized canonical header for that same immutable
boundary/hash. Use `--retirement-review` then `--retire REVIEW_HASH` with those
refs and `--event EVENT_JSON`. New events never refresh an old receipt's capture
time. Retirement requires that exact post-switch event in both native schemas,
current canonical local witness, complete framework coverage, actual API/queue
coverage, positive kernel attribution, drained owned backend tuples and retention
of the exact original boot symlink inode in the new operation directory.

Each effect writes an exclusive fsynced intent and ACK. Unknown SQL, start, stop,
reload or partial prefixes are inspected with `--inspect`; they are not retried.
This owner retains the predecessor's manual-reconciliation boundary for partial
switch/inverse prefixes. It does not manufacture a terminal/ready receipt after
a failed or lost action.

## Inverse and managed composition

Use `--inverse-review`, then the explicit `--inverse REVIEW_HASH`. The current
combined source may be the acknowledged restored epoch or its exactly qualified
terminal state. This operation does not start or stop that combined source. A
retired temporary scanner gets its original boot inode back, then one owned
source start. Its new SDK kernel actor must match the original Node/esbuild
programs, direct child relationship, UID/groups/NNP and exact retained capability
digest. Its private environment hash excludes only the two systemd-generated
restart fields; changed secrets or startup injection refuse. The loaded original
three writable and one read-only mount and the actual process namespace inodes
are checked. Its genuine new heartbeat must be newer than its stopped predecessor
and at least the pre-start DB clock, with a positive kernel-owned backend.

The old API resumes only after the temporary source is framework-ready and covers
the final accepted combined feature cursor. The inverse removes only its own98
files and eight grants, retains all schemas and artwork, and restarts the original
API/queue/timer with new owned receipts. Unknown restart actors are not adopted;
an inverse-only normal restart needs the exact original program/private context
and a positive systemd restart counter.

Exports:

- `validate_feature_leaf(result_sha, manifest_sha, input_sha)` validates the new
  retirement receipt, own collector/API/schedule/retired-scanner state and bounded
  availability. It grants no combined source, reader, financial or whole-graph
  authority. It never recursively invokes the three-reader leaf.
- `validate_inverse_leaf(result_sha, manifest_sha, input_sha, reader_inverse_refs=None)` validates the fixed
  new `inverse-result.json`, restored API/source/private/boot/native state and
  returns `temporarySourceActor` in SDK `{unit,parent,processes}` shape, plus its
  positive `temporarySourceKernelSessions`. Additional namespace and normalized
  environment hash fields are part of that exact owned actor.

The three-argument form qualifies the collector's exact restored143+cache4 graph
before the separate reader inverse. After reader recovery has removed cache4,
the caller must supply the explicit fourth argument
`{"result_sha": "ACTUAL_READER_INVERSE_SHA", "manifest_sha": "ACTUAL_READER_MANIFEST_SHA"}`.
The feature producer then invokes the fixed d5db completed-reader inverse helper
itself. That helper must qualify the same reader operation, READ admission/plan/
context, current full143 graph, all column ACLs, restored readers/global state and
reversed cache4/LOGIN changes. A caller-supplied success object is never accepted.

For this later phase, the expected collector graph comes from the authenticated
cache **before** receipt, while the original feature operation remains bound to
the cache **after** receipt. The unchanged pure reader-delta validator proves
that those two recorded collector snapshots differ by exactly the acknowledged
four relation OIDs, grantors and non-grantable SELECTs. Every other collector and
target-table/column field remains exact. The complete phase is rechecked after
actor, session and HTTP observations. Cache removal is not inferred by deleting
arbitrary current edges, and the feature inverse receipt's original capture-time
`prior143AndCache4Preserved` fact is never relabelled as a post-reader graph claim.

The inverse leaf checks only the temporary writer's positive subset of shared
role sessions. It does not demand global role-zero or inspect an obsolete de4
actor. The managed owner must independently map every competing writer and hold
the exact returned temporary actor stable before and after its own standalone
start. Reverse feature before reversing the three-reader peers captured by this
operation; the separate reader inverse then restores its own graph/LOGIN state.
The managed owner repeats the feature inverse leaf with the explicit completed
reader refs on both sides of its standalone source restart.
All composition remains same-boot and receipt-gated. A later managed forward
reader leaf must explicitly compose this new feature producer rather than report
an old e506 leaf passed.
