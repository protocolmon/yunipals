# Retained YPAL proxy current-invocation acknowledgement

This new helper acknowledges a semantic restart of the fixed retained 19212
proxy. It leaves c96, the original route receipts, 143 READ owner, and frozen
344f/efca reader package unchanged. The historical whole validator remains false;
the helper does not report that it passed or describe the restart as automatic.

Default review is read-only. It authenticates the c96/3a70/a80 source ancestry,
the original route operation and profile admission, then takes two complete
stable observations. All four combined routes retain their exact acknowledged
actors, code, dependencies, unit/env/boot inodes, profile, expiry, budget and empty
permit set. All four older retained proxies also retain their actual original
actors. The new 19212 invocation must preserve every recorded definition,
private-file hash, inline/file declaration, fixed process field, command,
executable, parent, privilege and cgroup fact. Only the explicitly captured
PID/start/invocation tuple and full live environment digest can differ.

The full environment check merges typed manager inline assignments and the
twelve effective required files in order. Private expected values travel only
over stdin to a same-UID peer, never command arguments or output. It rejects
unknown runtime keys and checks account variables, the actual invocation/PID,
journal FD identity, manager PATH/LANG and the systemd PSI fields. Its fresh raw
environment digest is bound deliberately; no old invocation-dependent digest
is substituted. Unsupported actual environment shapes refuse before capture.

The strict source component additionally proves the same accepted temporary
YPAL source/API, native catalog/type rules/queue and current combined source
actor, code, private files, build, table OIDs, boot and heartbeat. It does not
claim framework readiness, covered history, canonical witnesses, reader
selection or financial write authority.

## Review and exclusive capture

After separate code review/staging, root may run:

```sh
python3 -I -B "$OPS/ypal-retained-proxy-current-v1.py"
python3 -I -B "$OPS/ypal-retained-proxy-current-v1.py" --capture "$ACTUAL_REVIEW_HASH"
```

`OPS` is the fixed existing operations directory. Capture repeats qualification
and a final snapshot, then creates only the root-owned 0700 directory
`/var/backups/yunipals-ypal-retained-proxy-current-v1-20261024` and its exclusive
0600 `result.json`. The ACK contains summary identities, hashes and explicit
qualification flags, with no environment values or ownership rows. Existing
paths refuse; there is no overwrite, runtime restart, budget renewal, SQL write,
provider request, retry, credential copy or permission change. Detailed review
and ACK output stay private. No actual ACK is included in this source package.

## Explicit component interface

- `acknowledgement(actual_sha)` is a pure fixed-path protected ACK loader. It
  makes no database, API or provider request and grants no current authority.
- `validate_rpc_current(actual_sha)` rechecks only the exact RPC component.
  `qualified_rpc_components(actual_sha)` returns that proof plus actual observed
  RPC packets/routes/catalog for a separately authenticated successor. Neither
  touches the temporary YPAL source/API or combined actor, so later intentional
  retirement of those actors does not become an Arena dependency.
- `validate_source_current(actual_sha)` additionally rechecks strict current
  source preservation. `qualified_source_components(actual_sha)` returns its
  actual observed source packets as well. This component intentionally refuses
  later source/API/role-graph changes unless another exact phase-aware successor
  composes their real receipts.

RPC-only proofs explicitly return source, temporary-source/API, source-readiness,
reader-role and financial-write authority as false. Both current validators take
two fresh stable observations and require equality with the immutable captured
component. They never normalize an old observation or call an old whole guard.
Only cached loopback preflight/metrics/API GETs and read-only local SQL are used.

## Smallest downstream continuation

The old `start-source.py.check_preserved` calls the historical routes whole
validator and retained packet equality. The old registration binding delegates
to it; the c9 READ owner delegates its `source_binding` to that registration
binding. Those exact gates therefore remain stale after this restart.

A separately reviewed successor must explicitly consume this actual ACK, reuse
the unchanged static/native/source/role/boot leaves, and compare current semantic
RPC facts against this new component while preserving the original operation.
For the still-uncommitted 143 reads it must retain the exact private plan,
baseline ACL graph, existing roles/LOGIN state, grants and inverse, and produce
its own review/ROLLBACK/commit receipts. It cannot claim the old whole source
or c9 validator passed. Adoption/cache/reader contexts then consume that precise
new producer and acknowledgement chain. This package neither implements nor
silently authorizes that downstream closure. The frozen reader owner stays held.
