# Actual generation binding and thin publication adapters

This is source integration, not a new installation, attempt, candidate or
publication acknowledgement. Frozen V5/V6 files are unchanged.

The three small adapters compile byte-authenticated frozen V6 sources into new
namespaces: `ypal-ordinary-read-cache-bound-v1.py`,
`ypal-ordinary-reader-bound-v1.py` (both proof and coordinator), and
`ypal-ordinary-publication-bound-v1.py`. They record their actual source hashes,
new formats, journal roots and timing domains. Frozen producer387c/46bd,
reader7601 and callerc782 success is never substituted for their success.

The common helper `ypal-ordinary-generation-binding-v1.py` admits only its finite
version1 contract, fixed actual attempt owner/format/base/unit/work/application,
actual V5 dataset identity and the real V3 artifact/install source. It parses
the owner's literal `SOURCE_PINS` before evaluation, authenticates every declared
protected root-owned source file, and only then evaluates the owner. Basenames,
size limits, SHA-256 values, stable file identities and exact closure equality
are required. There is no URL, alternate import entrypoint or arbitrary path
escape. The current conservative V2 owner closure has164 source dependencies;
its exact map, rather than a count assumption, is authoritative.

The binding routes the actual V2 attempt producer and explicit semantic
recovery component `ca20dab6095290c78617a9ded63b21020c5e8aeda2e0de664d6947bbfa5f59ff`.
The new operation/candidate records name that component and explicitly deny
original strict-verifier success. All four verify/restore comparisons still
require exact count, SHA and tuple bytes; allocated bytes remain validated
observations. The original a194 component and capsule receipts remain immutable.
A physical FSM/VM allocation change is not relabeled as old-verifier success.

`ypal-ordinary-publication-bound-manifest-v1.py` builds both public manifests
from actual existing bytes. The generation manifest has no future hashes. The
reader source manifest authenticates its combined proof/coordinator role,
actual bound provider/caller, binding digest, complete generation closure and
all frozen V6 programs. The same actual combined source file supplies the
proof and coordinator roles, without aliases. It also derives cache-finish
from exact frozenec9 bytes, changing only its manifest and evidence identity.
Its new receipt domain/journal root and completed-inverse format are explicit;
all cache-finish lifecycle and validation bodies remain unchanged. Frozen V6 SQL, peers, wire and probe remain immutable ancestry. The actual

The old source manifest remains immutable ancestry.

`Phase.generation()` retains the complete original receipt checks and changes

The new proof's terminal method invokes the genuine new owner's narrow
terminal validator. That validator must authenticate the original archived

identities, private inputs and retained capsule bytes. It must work both
before and after publication. It does not assert that the current pointer is
still103 or that the database candidate remains unpublished after publication;
those predicates belong to the original separate prepublication/current
publication methods. A changed terminal actor or boot cannot use this split
to bypass validation.

The actual immutable reader acknowledgement is exported by
`ypal-ordinary-reader-bound-v1.py`. Its route and real source hash are recorded
in `acknowledgementRoute`. The typed external feature hook accepts only the
fixed `ypal-ordinary-feature-handover-bound-v1.py` and
`ypal-ordinary-feature-context-bound-v1.py` route under a separately supplied
actual feature manifest. Five explicit references bind the result, manifest,
input, owner and context source. The whole bounded feature source map is
protected and authenticated before owner evaluation. Its manifest must pin
this actual bound reader and provider. Its returned leaf must name this exact
recorded reader result, operation, publication, manifest, read config and cache
input/ACK. Both sides use immutable acknowledgement for ancestry; neither calls
the other's feature-aware reader leaf. No circular producer pins are needed.
Frozen feature/coordinator success and source/whole-validator authority claims
are refused. This source hook creates no feature receipt or event evidence;
the later real feature handover retains its stricter post-switch opening/claim
and full parity requirements.

Default imports and CLIs have zero database/service/provider effects. Effects
use the explicit bound caller Session, current source preflight/postflight,
actual input/source manifests, exclusive review/intent journals and actual
mode-specific timing qualifications. Unknown effects are reconciled, never
implicitly retried. Tests use synthetic records and do not create runtime or
business evidence.
