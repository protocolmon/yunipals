# Controlled same-build source recovery

This immutable v2 keeps v1 unchanged after its read-only review refused the
retained temporary scanner's original capability policy. The only privilege
correction matches that scanner's PID, start ticks, UID/GID/groups, NNP and full
capability-set hash to the authenticated original retained packet. Any changed
capability bit refuses. Combined-source and API processes still require zero
capabilities. All v2 operation, input, probe, transient-unit and overlay paths
are separate; no v1 evidence is overwritten.

This is a source-only preparation. It does not authorize a restart. The existing
registered build, manifest, release, physical namespace and shared `ponder_sync`
store remain the data ancestry. A separate immutable configuration file changes
only `database.poolConfig.max` from five to eight. The original complete source
inventory therefore identifies the base, **not the entire new runtime**. Every
accepted runtime records the overlay, configuration SHA and its actual process
epoch separately. Existing source receipts remain historical.

Ponder 0.17.5 divides these maxima into `[admin,user,readonly,sync]` pools of
`[2,1,1,1]` and `[2,2,2,2]`. Its historical worker opens a sync transaction before
awaiting upstream range data. A second sync connection may reduce cross-chain
starvation; this package does not establish that it fixes upstream Base failures.
No budget, financial profile, permit, source descriptor, ABI or private input is
changed. The original six-GiB limit, four-GiB Node heap and all sandbox settings
are retained.

The local actual build evaluates config, schema and handlers using the accepted
Ponder/dependency versions. It produces the same `71e2a7f3b7` build and all three
original content hashes, with twelve explicit HTTP fixtures, zero real provider
requests, zero database calls and zero socket attempts. `local-build.json` is
that actual output, formatted without changing its values. It is not a host
runtime receipt.

## Inverse and interrupted prefixes

`--inverse` owns the pool-eight source only. It can stop a failed owned epoch or
cancel its exact pending auto-restart without requiring upstream/API health for
the terminal drain. An escaped known PID, foreign definition, overlay inode or
boot link refuses. The inverse retains the overlay bytes and original boot
inode, restores the original loaded config, then starts that original program
once under a **new** actual epoch. It compares original and accepted safe and
finalized floors, retaining all legitimate new work. It never calls an old
checkpoint rollback and never relabels the new actor as the old receipt.

`--finish-inverse` is read-only reconciliation when the restored start intent
already exists. It accepts legitimate subsequent indexing progress and issues
no duplicate start or SQL. A pre-effect failed original stop can instead prove
the exact untouched original actor remains live. A recent predecessor heartbeat
alone cannot prove a successful restoration.

If interruption occurred after `inverse-reload-intent.json` but before reload,
`--complete-inverse-reload` is the explicit configuration-only completion: exact
original definition bytes/inodes, terminal worker, drained sessions and owned
removed overlay are required. It records a separate exclusive intent and sends
only daemon-reload, then leaves startup to the explicit inverse continuation.
It never retries source stop/start or SQL. An unknown completion ACK is inspected
against actual loaded state before continuation; foreign state requires separate
operator reconciliation.

`validate_source_current(result_sha, code_sha, input_sha, restored=False)` exports
the acknowledged source epoch only. It rechecks current RPC authority and actual
runtime/native identities, but grants no reader, metadata, Arena, global readiness
or publication authority. Downstream successors must explicitly compose this
new operational overlay and actual result; the old whole-source gate remains
false. Frozen managed/reader contexts that bind the original pool-five actor
continue to refuse until an explicit successor is reviewed.
Its current writer-session authority is explicitly unqualified; callers that
need that authority must map the live epoch's PostgreSQL sockets separately.
It does not permanently require a temporary scanner to remain running.

After actual startup, compare bounded samples of complete native checkpoints,
handler/flush metrics, per-chain RPC failures, kernel PostgreSQL ownership/waits,
memory and live pack readiness. Preserve actual failures and safe/latest recovery
distinctions. Neither a larger pool nor a live PID establishes performance
