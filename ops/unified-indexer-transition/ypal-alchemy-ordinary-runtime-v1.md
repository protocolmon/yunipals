# Ordinary Alchemy runtime handover

This producer owns one new source/proxy epoch after the actual catch-up closure
and the separately approved ordinary financial admission. It performs no SQL,
financial admission, allowance reset, profile renewal, consumer selection or
Solana action. Its default and `--sources` modes are inert.

The financial policy is the acknowledged ordinary policy: 2,000,000 total CU per
UTC day, 1,500,000 shared source CU, and 200,000 foreground reserve. Actual
bookings determine available headroom. BNB keeps paid event queries with public
numeric headers and the existing bounded fallback; the other three chains keep
paid primary routing. All use the existing profile and its original expiry.

## Finite forward phases

Every command below also requires `--input-sha ACTUAL_INPUT_FILE_SHA`.

1. `--prepare` verifies the actual old closure and current financial admission,
   source/native44/cache/recovery/serving boundaries. It creates five exclusive

   definition files, and its private immutable operation. It starts nothing.
2. `--retire` stops only the six exact old timers once, verifies their six

   twelve definitions, two completion drop-ins and original source `99` inode

3. `--proxy ethereum`, `--proxy base`, `--proxy polygon`, `--proxy bnb` each stop

4. `--start` publishes its own source drop-in, then proves actual cache prefix

   three RO bindings before the sole start. Pool5, build71e, native44 and the
   existing sync cache are preserved.
5. `--current ACTUAL_RUNTIME_RESULT_SHA` rechecks the acknowledged source,

   canonical acceptance is separately qualified.

Every manager effect has an exclusive fsynced intent. A present start intent is

## Recovery

`--return-free` stops only the owned ordinary source and proxies, restores and
acknowledges the exact original four free proxy definitions, and emits its own
quiet receipt. A source DB failure does not prevent stopping owned processes or
returning proxies: the source drain flag remains false until separately proven.
Saved PID/start and backend PID/start epochs must disappear; shared-role peers
are never terminated. Lost free-start acknowledgements are observed without a
second start. Repeated recovery does not stop an already acknowledged free actor.

The separately reviewed financial owner must then disable the four ordinary
permits with its own actual acknowledgement. This runtime performs no financial
SQL and never refunds counters or restores the old catch-up window.
`--resume-free ACTUAL_DISABLED_RECEIPT_SHA` authenticates that completed disable,
the four current free epochs, terminal source, actual fragment coverage and
serving frame before restoring the original source definition and starting it
once under a new free-source intent and ACK. Old timer files remain retired.

An unknown SQL outcome belongs to the financial owner's read-only XID
reconciliation. This runtime does not retry it. An unknown process action is
kept as an honest owned prefix; do not delete intents or rewrite receipts.

## Current source interface

`validate_current_source(result_sha, input_sha, retained_current=None,
inverse=False)` returns the new source domain. Active mode positively maps all
role73004621 sessions to the actual combined writer plus the independently
qualified temporary writer. A supplied `retained_current` callback follows the
unchanged Host contract; an empty temporary set needs its actual owned retirement
intent. It does not permanently require the initial temporary PID.

The stable `binding` includes the actual source epoch, six-mount/private/boot
ancestry, routing map, profile/ordinary financial receipt and retirement receipt.
Heartbeat, checkpoint progress and kernel session counts are observations.
`financialAuthorityQualified` and `currentCanonicalCoverageQualified` are false.
`managedHandoverAllowed` is true only for the actual restored free source plus
the completed ordinary permit-disable receipt. `inverse=True` requires an owned
terminal prefix and returns no active-writer authority. It never relabels the
old completion, de4 or c96 producer.

This is a same-OS-boot, once-started operator. It does not qualify a reboot,
supervised replacement epoch, recurring generation lineage or managed parent.
Those need their own explicit current-runtime composition.

Detailed operations, process/catalog observations and receipts stay root-only
under `/var/backups/yunipals-alchemy-ordinary-runtime-v1-20261024`. Only finite
hashes, counts and acceptance flags should leave the host.
