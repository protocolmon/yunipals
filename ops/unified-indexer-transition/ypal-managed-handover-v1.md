# Managed YPAL EVM and retained Solana handover

This is source preparation for a future owned transition. No managed service,
provider request, role change, database write or source restart has been performed
by this package. Its default command prints an unqualified static summary.

The owner reuses the reviewed launcher and service template without changing
their bytes. It preserves the existing native build, schema and all 44 relation
identities. Pool maximum remains five. No checkpoint, active projection pointer,
metadata selection, Arena identity, Solana schedule or usage row is copied or
rewritten.

## Ordered execution

Run the installed source with Python isolated mode. All runtime phases require
the actual external manifest SHA and root-private input SHA. The following names
are placeholders for checksums obtained from actual protected files:

```text
python3 -I -B ypal-managed-handover-v1.py
python3 -I -B ypal-managed-handover-v1.py --columns
python3 -I -B ypal-managed-handover-v1.py --manifest-sha ACTUAL_CODE_SHA --input-sha ACTUAL_INPUT_SHA
```

The last command performs a fresh read-only review. Its hash binds exact current
actors, complete boot/definition inodes, private configuration, code, authorization
and source identities. Native progress, ordinary Solana progress, clocks,
resources and temporary backend IDs remain actual observations and are recaptured
at their effect boundary; they are not authority substitutions.

Use separate explicitly invoked phases:

1. `--drain ACTUAL_REVIEW_SHA`: requalify the exact reviewed authority, create an
   exclusive protected operation, then stop only the acknowledged observer and
   old writers. Fresh kernel-owned database tuples are captured immediately
   before each stop intent. A final actor comparison occurs after intent fsync
   and immediately before the manager command. Shared role sessions belonging
   to metadata are retained. Freeze the full Solana usage prefix only after
   writers, owned sessions and the worker advisory lock are absent.
2. `--install`: preserve original boot and definition **inodes** in the root-only
   hold directory. Install the frozen parent and a dependency-only observer
   replacement. Preserve the three read-only source overlays and separate
   writable cache/codegen binds. The sole added network permission is the
   previously accepted fixed Helius IP list. No service starts in this phase.
3. `--start-parent`: record one durable start intent and issue one start. Check
   actual parent/child arguments, ordered three EVM files, separate Solana file,
   working directories, kernel identities, resource/network settings, mounts,
   native catalog and framework heartbeat. Current canonical readiness is
   deliberately checked after the observer starts, avoiding a cold-start cycle.
4. `--start-observer`: start the same official observer once with dependencies
   bound to the managed parent. Require advancing revisions for all four chains,
   fresh canonical probes, actual serving reader/cache/feature/Arena leaves and
   exact current graph before recording completion.

After a lost start acknowledgement, use `--inspect`, then the appropriate
`--reconcile-parent` or `--reconcile-observer`. These observe and may write an
acknowledgement; they never repeat a manager command. An incomplete observation
does not authorize rerunning a start phase.

The approved cold-start bound is between one and 300 seconds. Completion records
the observed before/after availability interval's upper bound. It makes neither
a zero-outage claim nor an exact HTTP outage-duration claim. Run the independent
actual route monitor across the real transition. Exceeding the reviewed bound
requires inspection or the owned inverse.

## Scheduled publication and restart acceptance

Initial managed completion explicitly leaves scheduled publication and supervised
restart unaccepted. `--scheduled ACTUAL_RESULT_SHA` waits for an ordinary,
genuinely new 10,000-asset run after the retained next-scan time. A resumed partial
run or a staged publication cannot satisfy it. The complete preexisting usage
prefix remains exact and credits/publication IDs cannot rewind. The owner never
triggers a scan, adjusts its schedule or renews credit authority.

After that acceptance, `--restart ACTUAL_RESULT_SHA` owns one bounded restart
rehearsal. It drains the observer and managed group, captures another stopped
Solana boundary, and starts the parent once. Continue with
`--reconcile-restart-parent`, `--start-restart-observer` and
`--reconcile-restart-observer` as appropriate. The new epoch must regain canonical
source readiness and actual serving acceptance. No new build or native namespace
is introduced.

`validate_source_leaf(result_sha, manifest_sha, input_sha)` supplies explicit
managed source/financial authority for later compositions. It rechecks the
current owned parent epoch, source identities, routes, full column catalog and
canonical readiness without calling Arena/reader leaves recursively.
`validate_current` additionally qualifies the observer and consumer phase leaves.
Normal systemd restarts are joined to exact definitions, boot inodes, kernel
tree, monotonic epoch and native identity; the original receipt's PID is not
relabeled.

## Owned inverse

`--inverse` and explicit `--finish-inverse` stop only the owned new observer and
parent, including a failed parent waiting on its own restart timer. The latter
case requires exact installed definitions and epoch, empty cgroup, and positive
attribution of remaining shared-role sessions to the unchanged metadata worker.
Unattributed sessions refuse; role-wide termination or session-age inference is
absent.

Every stop has a post-intent comparison. A timer race proven to have invoked no
command can receive one new explicit stop intent on `--finish-inverse`. A genuinely
unknown manager outcome is never retried. Terminal cgroup/session observation
can reconcile a lost stop acknowledgement.

The inverse freezes the newest legitimate stopped Solana state and preserves its
whole ledger prefix and publication. It restores original definition and boot
inodes, checks actual loaded commands after a potentially lost reload ACK, then
starts only previously active original programs under new owned start intents.
Current canonical source/serving acceptance is required before claiming restored
operation. If the original program actually started but its ACK was lost, finish
authenticates that new actor and keeps legitimate subsequent progress; it does
not issue a second start. A still-terminal unknown start remains unresolved.

An inverse before Solana was drained preserves the unchanged original writer;
it explicitly does not call a live, still-mutable ledger observation an immutable
prefix. There is no database restore, pointer rewrite, schedule reset, journal
deletion, credit refund or loss of external work.

`validate_restored_source_leaf(inverse_sha, manifest_sha, input_sha)` qualifies
the actual restored programs and their new owned epochs for a subsequent
composition. It keeps the current native catalog and canonical coverage checks,
but explicitly reports that the final managed target is not selected. Calling
the old c96 or f81 whole validator on those new PIDs would be incorrect.
