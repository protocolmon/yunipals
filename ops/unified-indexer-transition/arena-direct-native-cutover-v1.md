## Failure and inverse boundaries

Never rerun apply on an existing operation namespace. Read-only reconciliation reads only the same-boot owned operation and genuine recorded XIDs through `pg_xact_status`; a changed after-graph alone never proves COMMIT success.

```bash
python3 /opt/yunipals-unified/operations/free-replay-20261020/arena-direct-native-cutover-v1.py \
  --plan "$ARENA_CUTOVER_PLAN" --plan-sha256 "$ARENA_CUTOVER_PLAN_SHA" --reconcile
```

An owned pre-adoption inverse is available with `--rollback-review`, then `--rollback "$ARENA_CUTOVER_INVERSE_REVIEW_HASH"`. It requires no selector, two unchanged legacy identities, exact legacy/unhalted mode, and aborted status for every recorded transaction. It removes only captured native file inodes, restores only the captured old boot paths, and starts only the stopped original units. **It performs no database writes or private data restore.** A committed/unknown/in-progress adoption, changed invocation/file/link, changed boot, native-start intent or prior original-start attempt refuses inverse.

After adoption commits, the original runtime is not a compatible rollback target even if source publication or startup later fails. Keep the deployment halted, preserve the private backup and journals, and inspect reconciliation. Use explicit forward review for an owned interrupted adoption/publication/start/unhalt:

```bash
python3 /opt/yunipals-unified/operations/free-replay-20261020/arena-direct-native-cutover-v1.py \
  --plan "$ARENA_CUTOVER_PLAN" --plan-sha256 "$ARENA_CUTOVER_PLAN_SHA" --continue-review
python3 /opt/yunipals-unified/operations/free-replay-20261020/arena-direct-native-cutover-v1.py \
  --plan "$ARENA_CUTOVER_PLAN" --plan-sha256 "$ARENA_CUTOVER_PLAN_SHA" \
  --continue "$ARENA_CUTOVER_CONTINUATION_REVIEW_HASH"
```

Forward continuation requires the same boot/operator/plan, actual committed adoption XID, exact adopted identity/AAD and retained-ledger proof, unchanged guards/role graph/configuration, fresh canonical source proof and pool headroom. If publication is absent, only known terminal aborted selector attempts may be followed by a publish-only invocation of the official source switch. The original adoption is never repeated. If a selector COMMIT acknowledgement was lost, its actual row and immutable history must exactly match its own recorded XID/epoch/source/floor/review; SQL is skipped. Unknown/in-progress XIDs or foreign selectors refuse.

The exact prepared native file and boot inodes are retained. A lost boot-link acknowledgement can finish the same inode publication. Explicit continuation can start or resume only the owned worker namespace, after static manager/environment/credential checks, no queued job, and exact active-process/empty-cgroup/UID inventory proofs. It does not directly reissue a provider POST, signing call or broadcast: the tested fenced worker recovers its existing durable UUIDs/nonces/signed bytes. A legitimate active worker stays running. After a genuine committed unhalt only, child Python/ffmpeg processes are allowed when their UID/GID/NNP/effective privileges, exact native cgroup and bounded parent chain lead to that unit's stable main process. The strict eight-main-only check remains in force while halted. After stabilization, the original private input hashes are checked again before unhalt or a receipt-only finish. A healthy receipt-only finish reloads or starts no service. A changed or unknown actor/file/epoch refuses.

Unhalt uses the exact selected epoch. If its acknowledgement was lost, actual unhalted state is accepted only with that operation's genuine committed unhalt XID and epoch; no second UPDATE is issued. Each explicit attempt gets a distinct private attempt/result record (maximum8). Publication/unhalt continuation uses separate append-only journals and preserves the original journals/XIDs. No implicit retry exists.

A pre-adoption inverse whose old-runtime start acknowledgement is lost still requires inspection; it is not silently repeated. **Post-native rollback onto an isolated public source remains a separate full-goal task.** Nothing here rewinds the private database, recreates UUIDs/signed bytes, authorizes a new financial budget, or restarts the original legacy runtime after adoption.
