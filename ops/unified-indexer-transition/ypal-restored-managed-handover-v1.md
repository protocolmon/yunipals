These are not an automatic command chain.

1. Review requires current de4/994, actual all-four canonical source probes, reader/cache/feature/Arena leaves, the sustained observer, original Solana auth/config/budgets, resources, native44/cache, full ACL/columns, positive kernel-owned session attribution and all legacy activation paths. 2. Drain records fresh owned PostgreSQL pid/backend-start tuples immediately before each durable stop intent. It stops only the original combined source and, if active, original Solana worker. Known process epochs and captured sessions must be gone. It never requires all shared-role sessions to vanish. The stopped Solana stage, schedule, ledger prefix, usage and publication are retained.
3. Install moves original boot/parent-definition inodes into the owned hold directory using atomic no-replace renames. It publishes only the exact new unit, existing-provider egress and parent boot. 4. Start has one durable intent with a real prestart database clock and predecessor heartbeat. Final current acceptance requires both actual receipts and current consumer leaves.

A start, stop, rename or reload with an unknown acknowledgement is never automatically resent. `--accept` and `--accept-restart` observe issued starts only. The matching durable start intent is mandatory; no old PID or old heartbeat supplies success. A later unacknowledged automatic service epoch is refused by the current leaf; a separate explicit epoch-qualification policy remains necessary before it can carry final-supervisor authority. ## Full serving inverse

`--inverse-drain` stops only the owned managed parent, including a known failed/pending-restart state, without requiring forward readiness. It can complete an already-issued original stop by observation. An untouched original actor is preserved. A pre-drain inverse records an honest no-op, rather than claiming a new epoch.

The durable `inverse-drained.json` checkpoint means the managed parent is terminal, original definitions and all boot inodes are restored and loaded, and the original standalone source is still terminal. Only after that restoration does it call the frozen fbb terminal-source leaf. The unchanged observer remains running. This checkpoint is an intermediate, not a completed serving inverse.

While the source remains terminal, perform the separate feature operational inverse first while143+cache4 remain, then the full reader inverse which removes cache4/LOGIN and restores global103/metadata/legacy serving. The protected `/var/backups/yunipals-ypal-restored-managed-inverse-input-v1-20261024/input.json` then binds this operation hash, manifest hash and actual completed reader/feature inverse hashes. Both reference dictionaries use `result_sha` and `manifest_sha`; feature also requires `input_sha`. The managed owner explicitly passes those same completed-reader references into the feature's post-reader inverse leaf, which must qualify143 without pretending the removed four reads remain. No future receipt is guessed.

`--inverse-restart ACTUAL_INVERSE_INPUT_SHA` verifies both source-free leaves, records the reader's stable binding and actual restored temporary source actor, then issues the original standalone start once. It uses the original pool5/transport/namespace and a new heartbeat clock floor. It proves positive kernel subsets for both the new standalone and restored temporary pack source; shared metadata/Solana sessions are separately attributed. It restores an originally active Solana worker once when this operation actually drained it. The leaves and private/static/RPC/observer proofs are checked again before the new inverse receipt. Legitimate cursor/heartbeat progress is an observation, not a rewritten identity.

`--finish-inverse-drain` and `--finish-inverse-restart ACTUAL_INVERSE_INPUT_SHA` reconcile only owned prefixes. They do not repeat unknown stop/start commands. The new inverse receipt and `validate_restored_source_leaf` identify the new standalone epoch under this producer, never as old c96/de4. This source leaf proves current writer/heartbeat/backends while explicitly withholding source readiness, financial or reader authority.
