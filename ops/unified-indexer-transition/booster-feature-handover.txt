RECOVERY AND LIMITS

Each action has a private intent and acknowledgement. `reconcile` is read-only;
it reports hashes, current fixed unit states and missing acknowledgements, never
repeats a command. `--resume --apply <recorded reviewHash>` can adopt a completed
action only through its exact observation. A lost API start ACK is bound by
fixed unit/env/process/cgroup plus start monotonic time after the owned intent.
Queue PID/invocation/start fields may be cleared by systemd GC: completion then
requires a trusted same-boot structured journal event from UID967/GID961/pinned
Node in the exact unit after the intent, skipped=false and sufficient coverage.
Every stop command first rechecks the exact owned static definition and current
invocation/PID/start identity, twice, before recording command issuance. A
replacement fails without issuing stop. A terminal API/source with no command
marker cannot be adopted from blank systemd GC metadata. Only the exact queue
run may be adopted from a trusted natural completion, without issuing a stop.
Stopped actors can use empty invocation only with recorded prior ownership,
unchanged static files, terminal PID0/no job/empty cgroup and drained own pool.
Cross-boot partial action adoption is refused.

If the intended action did not actually complete, the owner does not repeat an
uncertain start/SQL automatically. Reconcile and use the explicit owned inverse
or a separately reviewed recovery. An unrelated restart/static-file change is
not permission to disable guards. Genuine future external event/header evidence
and actual final consumer admissions cannot be manufactured by this helper.
