# Bound reader and feature ancestry for Arena and managed handover

These are source adapters. They do not supply an Arena adoption result, a
managed result, a restored-source result, or current downstream acceptance.
The reader, feature, Arena and managed runtime owners still require their real
private inputs, reviewed phases, intents, process epochs and acknowledgements.

`ypal-ordinary-downstream-refs-v1.py` authenticates the actual bound reader and
feature programs. Its reader route is only the immutable
`acknowledgement(result_sha,manifest_sha)` from reader `7e378357…`, with source
manifest `bbd19325…`. The feature route is owner `2a6b2c59…`, context `9c025c89…`,
manifest `dda74ac6…`. The helper compares the exact reader operation,
publication, READ triple, cache-prepared and cache-input ancestry. Immutable
acknowledgements confer no current source or reader authority. No current
reader validator calls back into a feature validator.

The common `publicationRefs` object has exactly two groups:

- `reader`: `resultSha256`, `manifestSha256`.
- `feature`: `resultSha256`, `manifestSha256`, `inputSha256`, `producerSha256`,
  `contextSha256`.

All values must identify existing receipts or actual source bytes. The source
and manifest values are checked against the frozen bound graph. The feature
leaf and its separate `Host.retained_current()` are both required and repeated
around capture. The latter proves the genuine stop intent, gone process
epochs, terminal temporary source and empty actor set. An unproved empty set,
changed API, feature inverse or different reader ancestry refuses.

The feature implementation remains unchanged. Its retirement requires a real
canonical post-switch `RequestCreated` or `RequestCompleted`, exactly once
with all nine event columns equal in both schemas, and complete eight-table
parity. Normal opening/claim activity must supply that evidence. Source
controls do not create an event or authorize retirement.
