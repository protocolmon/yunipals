Cache-finish retained-stop successor proposal

This is a source proposal, before code adoption or effects. Frozen Reader5,
manifest `455c09d5…`, its callback qualification owner `fd6d00b8…`, and all failed
cache journals remain unchanged.

The executable no-effect reproducer is
[ypal-cont5-cache-finish-stop-ancestry.test.py](../../ops/unified-indexer-transition/ypal-cont5-cache-finish-stop-ancestry.test.py).
It constructs the actual Reader5 Proof and its derived cache-finish runtime,
then executes the genuine `review` body with explicit Context/current I/O
fixtures. The genuine stopped-cache check returns its retained-stop object;
the next original `oldCacheStoppedSha256` expression requests
`c.cache.BASE / 'stopped.json'`. That is the new CONT5 cache directory, which
deliberately has no new stop ACK. The review refuses before any service action.

The existing authority already provides the required truthful ancestry.
`cache.continuation_authority.stopped(cache,host)` authenticates the new baseline,
rehearsal and four-READ authorization against `before.binding.retainedActualStop`.
Its actual prior-stop route executes the unchanged old8be stopped-cache checks,
private/config and boot proofs, all old journal/inode bookends, old transaction
16540148 genuinely aborted, and old child/backend terminal proof. It returns:

```text
format: actual authority FORMAT + '-retained-stop'
actualPriorStopped: actual original stopped receipt
priorStoppedFile: old8be BASE / 'stopped.json'
priorStoppedSha256: SHA of that actual protected file
retainedBootArchiveFile: old8be BASE / 'original-boot-link'
newStopActionPerformed: false
```

The old directory is
`/var/backups/yunipals-ypal-ordinary-read-cache-accept-v2-20261025`.
The new CONT5 before record preserves the identical original actor, original
boot identity and nine-field cache configuration. Its retained-stop binding
names the old producer, actual aborted XID and complete record frames. The
missing file is therefore a cache-finish read-path error, not missing stop
authority.

The proposed owner is a new
`ypal-ordinary-cache-finish-retained-stop-v1.py` with its own literal source map,
source manifest, FORMAT, FILE, BASE and protected INPUT. It owns new operation,
start, acceptance and inverse-drain journals. Its source map pins actual
Reader5/provider5/authority5, manifest455c and the original cache-finish template;
it never pins the consumer mapper, Core3, a future receipt or an inverse caller.

The input contains only actual completed Reader5 refs
`{resultSha256,producerSha256,manifestSha256}` and the actual cache prepared SHA.
The complete Reader5 operation provides the ten original inputs and immutable
metadata epoch; the protected report/config and actual before record must agree.
Stop-file and boot-archive paths are derived from the fixed authority, never
accepted as user-selected paths. No future cache-finish result SHA is needed.

The compiler retains the entire original lifecycle and declares these seams:

1. The owner identity and journal directory become the actual new producer.
   The new owner's own source manifest authenticates it; it does not claim to
   be an extra file in the immutable455c reader manifest.
2. The sole stopped-file hash expression becomes a call to an authenticated
   retained-stop function. The operation binds the actual old stopped-file SHA,
   path, old producer, complete old record frames, new before/config SHA and
   original boot/archive identity. It does not create `newBASE/stopped.json`,
   copy an ACK, redirect a protected file read or report a new stop action.
3. The existing four exact boot-archive seams keep using the actual old archive
   inode. File moves and fsync retain that inode; no new boot link is substituted.
4. Source/context loading stays bound to the genuine unchanged Reader5
   controller and its actual completed result. A fresh actual Caller5 reader
   Session supplies its bound provider/metadata constructor and full current
   source checks before effects. The old unbound default factory is not used.

Before native start, the full genuine stopped/private/catalog/source/reader
checks run again and the old stop/boot frames are rechecked. After native start,
old unit-inactive checks are no longer current authority: current native actor,
private/config/loaded definitions, own start journal, four official freshness
proofs and all three reader health checks remain the original acceptance gates.
The old stop is immutable ancestry. An immutable ACK never calls a whole current
source proof or pretends the old unit is still inactive.

The new owner should expose these finite APIs:

```text
runtime(root, proof, inputSha256)
  -> actual new cache-finish namespace, with its own FORMAT/BASE and original
     review/start/reconcile/accept/drain/restore methods
acknowledgement(resultSha256, inputSha256)
  -> immutable new-producer ACK binding the actual Reader5/old-stop lineage;
     current/source/READ/financial authority false, effects0
```

The effect dispatcher retains the original transition and generation locks,
one owned action/intent, exact start invocation/minimum ticks, terminal/session
proofs, explicit recovery and no automatic replay. Native worker startup and
freshness acceptance are separate actions. No service is started by a factory or
immutable ACK.

There is a required downstream contract change. The still-unpublished mapper3
and Core3 should accept optional exact `cacheFinish` refs
`{inputSha256,producerSha256,manifestSha256}`. They authenticate the new owner's
entire literal source manifest before evaluation, then replace only the
`root.cache_finish_module(context)` factory route for the actual cache, stop,
restore and journal-frame bodies. Those bodies inspect the actual new owner's
BASE and retained original cache provider/unit. An existing completed result is
authenticated by the new pure ACK; no future result SHA is stored in an input.
Null/default cannot qualify a new owner's active or stopped native worker.

Core3's input can point to this actual protected cache-owner input. The cache
owner input points only upstream to the already completed Reader5/cache records,
so it never points back to Core3. The metadata-inverse supplemental-ref API keeps
its existing acyclic shape. A separately reviewed inverse-only caller must use
this same new cache-finish factory so owned drain/restore follows its real
journals. The frozen Reader5 graph and initial timing driver need no edit.

The proposed validation includes the actual missing-path reproducer, a positive
real returned-stop shape, wrong config/producer/file SHA/inode/boot refusals,
complete original lifecycle code comparisons outside declared seams, real
exclusive journal/boot-file fixtures, native-start gap and lost-ACK reconciliation,
four-freshness/three-reader acceptance, and real mapper/inverse callback cuts.
The proposal does not claim that those new controls or actual effects have run.
