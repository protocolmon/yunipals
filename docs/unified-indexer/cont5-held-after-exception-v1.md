# CONT5 held qualification: post-failure exception witness

This source-only helper preserves the actual caught inner error after a genuine CONT5 qualifier has already failed. It installs no live tracer or profiler and wraps neither the SQL parent nor any subprocess or pipe. Default execution is inert. It performs no query, current proof, approval refresh, dispatch, retry or receipt write.

`Witness(original_error, authority)` authenticates the complete fixed authority5 source manifest and its 20 actual files, reconstructs its static namespace, and compares the complete qualifier and wrapper code identities. It then examines only the original outer exception's bounded traceback. A matching frame must use the actual supplied qualifier code and globals and the cache bound to that authority. The genuine `_qualify_held` body retains its caught inner exception in its `error` local after unwinding. The helper retains that same exception object and exposes a private `snapshot()` of its class, message and traceback. Missing inner errors or unrelated outer frames remain explicit absence. Unknown source, code, namespace or cache bindings refuse.

The root caller must invoke this helper only in its original exception handler. A diagnostic refusal must never replace the original error or its saved traceback. The helper neither accepts a qualification nor reconciles transaction outcome. The original child/backend/XID and full catalog reconciliation remain separate required work. Its private snapshot must not be exported as raw user-facing output.

The proposed observation scope keeps coarse root phase timestamps and the existing passive command diagnostic, while installing neither the global `5b3` call profiler nor the `7bf` live trace/Popen observer. The genuine qualifier, prepared callback, SQL parent, source and metadata predicates, approval lifetime and five-second reserve stay unchanged. No held successor or dispatch is included in this packet.

Actual benchmark `cc93244807846b903989e31767d1b31d648ae111daa72e41a4b9df0b1efaa6da` measured the same 60,918-entry dependency preauthorization proof: 25.437896673 seconds without the two observers and 101.599053468 seconds with both. CPU times were 22.443309699 and 101.573957814 seconds. This establishes an observed cost difference for that one read-only filesystem operation. It does not isolate either observer or measure an uninstrumented held callback, and it provides no timing or source authority.

The actual failed HELD6 telemetry recorded 85.827942524 seconds of approval remaining at launch and a prepared callback that unwound after 112.293490340 seconds. The callback duration already exceeded the remaining budget less its unchanged five-second reserve. Nested profile durations are inclusive and must not be added. The publication error was `Native Base metadata unavailable` with detail `base_metadata_approval_pending`; the combined SQL predicate covers freshness, frontier, identity, implementation, checked boundary and state. These observations alone do not identify the exact failure-time subcondition or prove that removing observers makes the full callback fit.

Nine local controls execute genuine CONT5 qualifier bodies, the real provider/authority and rollback/prepared compilers, with explicit private receipt, catalog and transport fixtures. They verify retained exception identity, restored original parent, no live observer installation, source/code/cache drift refusals and preservation of existing observer state. These controls perform no production qualification, SQL transport or service action. Earlier frozen root drivers and failed journals remain unchanged.
