# SHA256 computation reuse with TimeoutError propagation

`ypal-readonly-sha256-memo-v2.py` is a separate source successor to frozen v1 `432d52299ad7040c2c587cb6db92b6aba4ff6fffd4d0adad499cfe604b08b9a0`. V1 is unchanged. V2 changes only its format to `yunipals-readonly-sha256-memo-v2` and adds `except TimeoutError: raise` immediately before each of the seven optional `_CACHE_ERRORS` handlers. Ordinary `OSError`, `MemoryError` and the other declared finite cache refusals retain their original behavior. TimeoutError and subclasses now propagate as the exact original exception object instead of becoming an optional cache miss or bookkeeping refusal. The packet contains no application/Source predicate, file-read, query, cache eligibility, lifetime, deadline or effect-protocol change.

The issue is reproducible through the public scope: injecting a `TimeoutError` at the optional lookup boundary during a large-input `hashlib.sha256` call returns a digest in v1 because TimeoutError inherits OSError. V2 propagates that same exception object and restores the original constructor/releases payloads. This is a defect in v1's general optional-error contract, not evidence that the completed read-only runner4 suppressed its actual alarm: that runner's alarm raises RuntimeError, which is outside v1's finite catch tuple and propagates. No v1 performance receipt is relabelled as v2 adoption, and no service or running operator is changed.

The API and scope requirements remain `SHA256Memo(maximum_payload_bytes=256*1024*1024, maximum_entries=4)`. Exact freshly supplied builtin immutable bytes, distinct security modes, independent copies of private original OpenSSL states, four-entry LRU and payload limits, unsupported/mutable call forwarding, exact original constructor errors, same-inode changed-byte refusal and alias-after-close behavior are retained. The original hash constructor is restored before counters/snapshots/writes, and payloads are released on both outcomes. There is no fact, code, parser, file-identity, current/source, actor, catalog, readiness or query cache. CPU observers that also wrap SHA256 must not overlap this helper.

The seven exclusions cover optional close counters, counter increments, error-counter increments, eligibility checks, lookup/hit-copy work, hit-LRU refresh and miss private-copy/store work. A deadline during any one of those operations must escape. This includes a TimeoutError raised after the original miss constructor has already returned; v2 propagates it without calling that constructor again. An optional ordinary OSError or MemoryError still returns the already computed miss object, or makes at most one fallback constructor call if no original has yet run. An external deadline during scope close still restores SHA and clears private payloads before propagating.
